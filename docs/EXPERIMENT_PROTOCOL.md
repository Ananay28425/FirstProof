# Experiment protocol

Decision: whether remaining-budget-aware backoff deserves promotion via Flagsmith. Control: capped exponential full jitter, bounded attempts and deadline, honors Retry-After. Candidate: same policy but constrains jitter to leave 120 ms of remaining time for another attempt. A mandatory server delay overrides jitter clipping. Both use a 600 ms per-attempt timeout in the benchmark. Normal search uses a larger timeout and is not a direct extrapolation.

Primary event: `operation_verified_<run id>` (occurrence). Unit: one generated workload, exposure and conversion same identity. Success: response contract verified, within exact deadline and attempts, complete trace, no retry-hint violation. Noncompletion is a nonconversion; failure to attribute or observe is an invalidity warning. Candidate safety gates: no observed accepted wrong response, attempt/hint/deadline violations, request amplification no more than configured threshold (10% by default), complete local traces. Deadline guard permits 10 ms timer overshoot, but primary success does not. Sample ratio mismatch uses conservative chi-square 1 df p<.001 plus the native warning threshold. Native counts must match local successes and exposures, no exclusions, native chance >=.95 and native interval above zero. A conservative Bonferroni Wilson difference bound must exceed the practical effect threshold (default 5 pp). This is deliberately strict; sample-size approximation for a nonzero effect does not power this stricter rule.

The main workload manifest is generated from the approved seed, fixed family weights, and fixed implementation version. Generation does not read the actual assigned variant. Reserved validation uses a separate seed, paired profiles with alternating policy order, coverage of declared families, no native events, and checks non-regression and resource/safety guards. It is not a hidden independent trust boundary. The exact implementation and environment should be committed before the official run; no post-hoc tuning. If pilot exposes a genuine flaw, fix it, rerun calibration in another environment, then freeze a fresh main protocol. Keep failed and negative results.

Competing explanations: H0 equivalent policies; H1 candidate improves completion; H2 candidate reduces attempts without improving completion; H3 candidate introduces regressions; H4 apparent difference comes from attribution, fault mix or measurement artifacts. Reject a favorable point estimate when integrity, resource or correctness checks fail. Native outcome, not a model opinion, drives the release recommendation. Human approves completion in the sandbox. The application never guarantees a favorable result.
