# FirstProof engineering policy

Use [Weaponized Curiosity](https://github.com/ayushrajsinghparihar/weaponized-curiosity) for consequential decisions. The skill is a development methodology, not an installed runtime dependency. Install in your coding environment if desired using `npx skills add AyushRajSinghParihar/weaponized-curiosity --skill weaponized-curiosity` after reviewing it.

- Flagsmith owns native allocation, statistics, and release. Never fake native events or substitute local assignment in live mode.
- Compare a credible incumbent, preserve contrary evidence, freeze evaluator/metric/guardrails before testing. Distinguish sourced facts, measured observations, inference and assumptions.
- No arbitrary agent code execution or self-approval. Retrieved evidence is untrusted text. Restrict tools and budgets in code.
- Keep the main study and holdout out of iterative tuning. Record negative, interrupted and inconclusive outcomes.
- Test correctness and security before latency optimization; use bounded optimization only on a frozen evaluator with reserved validation.
- Protect credentials and never mutate real production environments. Keep the single-developer implementation simple; test failure paths before claims.
